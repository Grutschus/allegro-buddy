# AGENTS.md

allegro-buddy (`ab`) is a Rust rewrite of the Python Slurm CLI allegro-buddy 2.7, with
identical behaviour. What it does and how users install it: [README.md](README.md);
development, compatibility and releasing: [CONTRIBUTING.md](CONTRIBUTING.md). This file
is for agents working on the code; keep it short and pointer-style.

## The invariant

Everything observable must stay identical to allegro-buddy 2.7: stdout/stderr bytes
(ANSI included), exit codes, files written, and the mutating Slurm calls (in order).
Read-only queries may start early or be replaced by cheaper ones carrying the same
information (`src/core/fast.rs`, version-gated; the only extra file is the
`slurm-version.<host>` cache). Like click, the program calls itself by the name it was
started as (`ab`, `allegro-buddy`, or the aliases `bab`, `better-allegro-buddy` from the
former fork: `cli::prog_name`); hints say `ab` (`core::CLI_NAME`). The few deliberate
deviations (the version among them) are listed in CONTRIBUTING.md ("Compatibility with
2.7"); don't add new ones unless asked. Performance work is welcome only under this rule.

- Python reference source: commit `91689b9` (= tag `v2.7`, the last Python release), e.g.
  `git show 91689b9:src/allegro_buddy/core.py`; its tests are under `tests/` there.
  Rust items name what they port (`Mirrors core.foo`), so grep for the Python name.
- Pinned Python dependencies whose behaviour is reproduced: rich 15.0.0, click 8.3.2,
  rich-click 1.9.9.
- Checking it: `cargo test` (byte-exact snapshots of 2.7's output), and for any change
  to output, parsing or Slurm calls a comparison with the Python reference (commit
  `91689b9`) on the same input.

## Where to start reading

- `src/lib.rs`: the ground rules and the Python -> Rust module map. Read it first.
- The `//!` header of each module holds its contract, e.g. `src/core/slurm.rs`
  (running commands, concurrency), `src/hooks.rs` (test hooks), `src/render/table.rs`.
- `tests/snapshots.rs` with `tests/fake-slurm/` (fixture format in its `index`).
- `Cargo.toml`: features and the deliberately minimal dependency list (each justified).

## Build, lint, test

Stable Rust, at least the `rust-version` in `Cargo.toml` (the MSRV CI builds with).

```sh
cargo fmt --all --check
cargo clippy --all-targets --locked -- -D warnings
cargo clippy --all-targets --locked --features test-hooks -- -D warnings
cargo test --locked
cargo build --release --locked    # what ships: no test hooks
```

CI (`.github/workflows/ci.yml`) runs these plus an MSRV build and macOS, only for
pushes to and PRs into `main`, and skips docs-only changes. Run them locally.

- `UPDATE_SNAPSHOTS=1 cargo test --test snapshots` rewrites `tests/snapshots/`. Those
  files are output of the Python reference: never regenerate them from `ab` to make a
  failing test pass; a diff there means behaviour changed.
- `src/render/{data,cell_tables,emoji_data}.rs` and `src/cli/themes.rs` are generated by
  `tools/gen_rich_data.py` (command in its docstring). Don't edit them by hand.
- Several agents at once: one git worktree and one `CARGO_TARGET_DIR` each.

## Conventions

- `std::process::exit` only in `src/main.rs`. `die()` (`src/error.rs`) prints and
  *returns* an `AbError`; propagate it with `?` / `return Err(die(..))` (`--watch`
  recovers from it).
- Print through `render::console` (`stdout()` / `stderr()`), never `println!`.
- Clock, user, groups, hostname and stdin-is-a-tty only through `src/hooks.rs`. The
  `BAB_TEST_*` variables are read only with the cargo feature `test-hooks` (`cargo test`
  turns it on via the self dev-dependency); release builds never have it.
- Table cells: `Cell::Text` is an already styled Rich `Text` and renders as is;
  `Cell::Str` is a Python `str` that Rich parses as markup (so a job named
  `[bold]x[/bold]` renders bold). Use the variant matching what the Python code passes.
- Slurm only through `src/core/slurm.rs`. Read-only queries the command is about to
  make may start at once (`slurm::prefetch`; one left unused when an earlier call dies
  or the data turns out not to need it is fine); results are evaluated, and errors
  reported, in Python's order. Never add, reorder or parallelize mutations (`sbatch`,
  `scancel`, `scontrol update`, `ssh`/`srun`); don't add calls to the common path
  unless they are much cheaper.
- The fake Slurm (`tests/fake-slurm/`) fails closed: a new call form
  needs a fixture whose data matches what the fake answers to Python's query.

## Real clusters (Allegro or any Slurm)

- Read-only commands only: `-h`, `--version`, `info`, `free`, `q`, `why` (no `--fix`),
  `node`, `job history/output`, `config show`. Never `dev start/stop/login`, `l`,
  `--watch`/`-w`, `why --fix`, `completion --install`, nor `sbatch`, `scancel`,
  `scontrol update`, `srun`, `salloc` yourself.
- The Python reference there is a private venv's console script (`bench/RESULTS.md`),
  never `/usr/bin/ab`: that is Apache Bench.
- Binaries for a cluster: built without `test-hooks`, on a host whose glibc is not newer
  than the cluster's (or a release binary).
